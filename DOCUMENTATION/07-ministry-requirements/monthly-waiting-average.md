# المتوسط الشهري للإنتظار (Monthly Waiting Average)

## نظرة عامة

قسم المتوسط الشهري للإنتظار يعرض متوسط أوقات انتظار العملاء حسب المدن خلال فترة زمنية محددة، وهو أحد متطلبات وزارة النقل. يتيح للمستخدمين فلترة البيانات حسب الفترة الزمنية والمدن، مع إمكانية تحميل البيانات المحددة بصيغة CSV.

---

## الصفحات

### 1. صفحة المتوسط الشهري للإنتظار

- **المسار:** `/ministryRequirements/monthlyWaitingAverage`
- **الملف:** `app/[locale]/ministryRequirements/monthlyWaitingAverage/page.tsx`
- **الوصف:** عرض متوسط أوقات الانتظار حسب المدن مع إمكانية الفلترة والتحميل

#### API Calls

##### 1. جلب قائمة المدن/المناطق

| الخاصية | القيمة |
|---------|--------|
| **Endpoint** | `/wasl/provinces` |
| **Method** | `GET` |
| **Response Type** | `ProvinceResponse` |
| **Cache** | No cache (`no-store`) |

**البيانات المُرجعة:**
```typescript
{
  success: boolean;
  code: number;
  message: string;
  data: Province[];
}
```

**Province Interface:**
```typescript
interface Province {
  region_id: number;
  region_name: string;
  created_at: string;
  updated_at: string;
}
```

---

##### 2. جلب بيانات المتوسط الشهري

| الخاصية | القيمة |
|---------|--------|
| **Endpoint** | `/wasl/waiting-averages` |
| **Method** | `GET` |
| **Response Type** | `WaitingAveragesResponse` |
| **Cache** | `no-store` |

**Query Parameters:**
```
?from=YYYY-MM-DD
&to=YYYY-MM-DD
&region_ids=1,2,3
```

**ملاحظات:**
- معامل `from` و `to` مطلوبان (required)
- معامل `region_ids` اختياري (إذا لم يُحدد يتم جلب بيانات "كامل المملكة")
- التواريخ يجب أن تكون بصيغة `YYYY-MM-DD`

**البيانات المُرجعة:**
```typescript
{
  success: boolean;
  code: number;
  message: string;
  data: Array<{
    region_name: string;
    average_waiting_time: string; // مثال: "5.23 دقيقة"
    from: string; // YYYY-MM-DD
    to: string;   // YYYY-MM-DD
  }>;
}
```

---

##### 3. تحميل البيانات كملف CSV

| الخاصية | القيمة |
|---------|--------|
| **Endpoint** | `/wasl/waiting-averages?download=true` |
| **Method** | `GET` |
| **Response Type** | `Blob (CSV file)` |

**Query Parameters:**
```
?from=YYYY-MM-DD
&to=YYYY-MM-DD
&region_ids=1,2,3  (اختياري)
&download=true
```

**ملاحظات:**
- إذا لم يتم تحديد `region_ids`، يتم تحميل بيانات كامل المملكة
- إذا تم تحديد `region_ids`، يتم تحميل البيانات للمناطق المحددة فقط
- اسم الملف: `monthly-waiting-data-{timestamp}.csv`

## الفلاتر المتاحة

| الفلتر | النوع | الوصف | Parameter |
|--------|-------|-------|-----------|
| من تاريخ | `Date` | تاريخ بداية الفترة | `filters[date][min]` |
| إلى تاريخ | `Date` | تاريخ نهاية الفترة (لا يمكن أن يسبق تاريخ البداية) | `filters[date][max]` |
| المدن | `Multi-Select` | اختيار مدينة أو أكثر (اختياري) | `filters[cities]` |

**القيم الافتراضية:**
- **التواريخ:** الشهر الماضي بالكامل (من أول يوم في الشهر الماضي إلى آخر يوم)
  - يتم حسابها تلقائيًا عند تحميل الصفحة
  - مثال: إذا كان التاريخ الحالي في مارس 2026، يتم عرض بيانات فبراير 2026 (من 2026-02-01 إلى 2026-02-28)
- **المدن:** غير محددة (يتم عرض بيانات "كامل المملكة")

## سلوك الفلاتر

### 1. التواريخ

**السلوك الافتراضي:**
- يتم تعيين الشهر الماضي تلقائيًا عند تحميل الصفحة
- إذا كان التاريخ الحالي في مارس 2026:
  - `dateFrom`: 2026-02-01
  - `dateTo`: 2026-02-28

**القيود:**
- حقل "إلى تاريخ" لا يمكن أن يسبق "من تاريخ"
- يتم إرسال التواريخ إلى API بصيغة: `YYYY-MM-DD HH:MM:SS`
  - `from`: `YYYY-MM-DD 00:00:00`
  - `to`: `YYYY-MM-DD 23:59:59`

**إزالة فلتر التاريخ:**
- عند إزالة "من تاريخ"، يتم أيضًا إزالة "إلى تاريخ" (لأن API يتطلب كليهما)
- يمكن إزالة "إلى تاريخ" بشكل منفصل

---

### 2. المدن

**السلوك الافتراضي:**
- لا يتم تحديد أي مدينة افتراضيًا
- عند عدم تحديد مدن، يتم عرض بيانات "كامل المملكة"

**التفاعل:**
- Popover قابل للبحث يحتوي على جميع المدن
- يمكن اختيار عدة مدن (Multi-select)
- يتم عرض المدن المحددة كـ badges أسفل الـ Popover
- كل badge يحتوي على زر (X) لإزالة المدينة

**إرسال إلى API:**
- إذا تم اختيار مدن: `region_ids=1,2,3`
- إذا لم يتم اختيار مدن: لا يتم إرسال معامل `region_ids`

---

### 3. الفلاتر النشطة (Active Filters)

**العرض:**
- يتم عرض جميع الفلاتر النشطة كـ badges باللون الأزرق الفاتح
- كل badge يعرض: "اسم الفلتر: القيمة"

**أمثلة:**
```
من تاريخ: 2026-02-01
إلى تاريخ: 2026-02-28
المدن: الرياض, جدة, الدمام
```

**إزالة فلتر:**
- كل badge يحتوي على زر (X)
- النقر على (X) يزيل الفلتر ويعيد جلب البيانات تلقائيًا

## سلوك البيانات

### 1. جلب البيانات

**متى يتم جلب البيانات:**
1. عند تحميل الصفحة (إذا كانت هناك معاملات في URL)
2. عند النقر على زر "تطبيق الفلتر"
3. عند إزالة فلتر نشط
4. عند تغيير معاملات URL

**الشروط:**
- يجب تحديد تاريخ البداية والنهاية
- إذا لم يتم تحديد تواريخ، يتم عرض رسالة "الرجاء تحديد الفترة الزمنية..."

---

### 2. التحديد (Selection)

**السلوك:**
- يتم إعادة تعيين التحديدات عند تغيير البيانات
- يمكن تحديد جميع البطاقات عبر checkbox "تحديد الكل"
- يمكن تحديد بطاقات فردية عبر checkbox كل بطاقة

**العداد:**
- يتم تحديث العداد في الوقت الفعلي: "تحديد الكل (X من Y)"
- عند تحديد الكل، يتم تحديد checkbox "تحديد الكل"

---

### 3. التحميل (Download)

**الخطوات:**
1. التحقق من وجود فترة زمنية (from & to)
2. التحقق من وجود بطاقات محددة (selectedItems.length > 0)
3. استخراج region_ids للبطاقات المحددة
4. إرسال طلب GET إلى `/wasl/waiting-averages?download=true`
5. تحويل الاستجابة إلى Blob
6. إنشاء رابط تحميل وتنزيل الملف
7. تنظيف الذاكرة (URL.revokeObjectURL)

**معالجة الأخطاء:**
- إذا لم يتم تحديد تواريخ: `alert("الرجاء تحديد الفترة الزمنية أولاً")`
- إذا لم يتم تحديد بطاقات: `alert("الرجاء اختيار بيانات للتحميل")`
- عند فشل التحميل: `alert("فشل تحميل البيانات. الرجاء المحاولة مرة أخرى")`

## تحويل البيانات (Data Transformation)

### من API إلى Component

**API Response:**
```json
{
  "data": [{
    "region_name": "الرياض",
    "average_waiting_time": "5.23 دقيقة",
    "from": "2026-02-01",
    "to": "2026-02-28"
  }]
}
```

**Component Data:**
```typescript
{
  id: 0, // index
  province_name: "الرياض", // من region_name
  average_waiting_time: "5.23 دقيقة",
  from: "2026-02-01",
  to: "2026-02-28"
}
```

**ملاحظات:**
- API يرجع `region_name`، لكن Component يستخدم `province_name`
- يتم إضافة `id` باستخدام index إذا لم يكن موجود في API
- يتم التحويل في `fetchWaitingAverages` function

## ملاحظات تقنية

1. **Lazy Loading:** مكون الفلترة يتم تحميله بشكل ديناميكي مع skeleton loader
2. **Client Component:** المكون يعمل في بيئة العميل (`"use client"`)
3. **URL State Management:** حالة الفلاتر تُحفظ في معاملات URL للمشاركة والـ navigation
4. **Auto-initialization:** الفلاتر الافتراضية (الشهر الماضي) تُطبق تلقائيًا عند التحميل
5. **Date Formatting:**
   - عرض التواريخ: `DD/MM/YYYY` (باستخدام `convertDateFormat`)
   - إرسال إلى API: `YYYY-MM-DD HH:MM:SS`
6. **Error Handling:** معالجة الأخطاء مع console.error و alerts للمستخدم
7. **Cache Policy:** جميع API calls تستخدم `cache: "no-store"` للحصول على بيانات محدثة
8. **Responsive Design:** Grid متجاوب يتكيف مع أحجام الشاشات المختلفة
9. **Skeleton Loading:** 6 بطاقات هيكلية أثناء التحميل
10. **Selection State:** يتم إعادة تعيين التحديدات عند تغيير البيانات
11. **Formik Integration:** إدارة النماذج باستخدام Formik
12. **Breadcrumbs:** استخدام أيقونات `ShieldTick` و `Flash` في التنقل التفصيلي
13. **Valid IDs Only:** فلترة المدن للتأكد من صحة `region_id` قبل الإرسال للـ API
